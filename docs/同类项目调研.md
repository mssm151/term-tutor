# SSH 终端 Agent 同类项目调研

调研日期：2026-10-31。

筛选目标：提供终端或终端集成，AI 能结合 SSH 会话输出主动调查远端环境，目标机器无需安装或配置 AI Agent。

补充确认的产品条件：类似 MobaXterm 的桌面终端客户端自身内置 Agent，不依赖学生另装 Claude Code、Codex 等外部 Agent CLI。用户明确认为 Clide 接近设想：以其终端与侧栏协同交互为主要参考，右侧提供自有教学 Agent 对话栏；模型调用、探索规划与工具循环由本项目实现。Electerm、korTTY 和 Warp 用于补充研究内置 Agent 的实现方式。aissh 同时有直接模型 API 后端，不应一概视为依赖外部 CLI，但其 SSH 工作区形态与目标桌面客户端仍有区别。

证据范围：项目官方 README 与官方文档。尚未安装运行或完成源码审计，功能、兼容性与可靠性仍需实测；不将宣传中的安全保证视为独立验证结论。

## 优先补充：Electerm，自带 Agent 的桌面终端客户端

- 本身是开源多会话终端与 SSH/SFTP 客户端，桌面端使用 Electron。
- 官方说明 AI 侧栏支持直接配置模型 API，Agent 模式可以在终端运行多步任务，无需外部 Agent CLI。
- 适合研究终端、连接管理、文件管理和内置 Agent 的整合方式；本次未实测桌面 Agent 全流程，也未找到覆盖所有功能的远端零组件保证，不将这一点视为已独立验证。

来源：[官方仓库](https://github.com/electerm/electerm)、[官方产品介绍](https://electerm.org/blogs/electerm-introduction/)、[内置 AI 服务说明](https://ai.electerm.org/about/)。

## 1. Clide：主要交互参考，自有 Agent 替换外部 CLI 依赖

- 本地 AI 通过 MCP 操作已打开的 SSH PTY，并读取终端输出；官方明确表示远端不需要 Agent。
- 工具包括 `getTerminalContext`、`runShellCommand`、`listRemoteFiles` 与 `readRemoteFile`；文件读取走 SFTP。
- 官方说明资源监控使用独立 exec 通道，不占用交互 PTY；AI 命令则可进入学生正在使用的 PTY。
- 采用 Tauri 桌面框架，其会话与工具桥接思路可供 Electron 实现参考。
- 差异：面向运维，允许 AI 操作真实终端；本项目需额外设计探索与教学任务的分工。
- 用户认可其交互形态。本项目参考其终端与对话侧栏协同、SSH/PTY、SFTP 和工具接口设计，自行实现 Agent 编排与模型调用，不保留对外部 Agent CLI 的必需依赖。

来源：[官方仓库及工具说明](https://github.com/DLbury/clide)。

## 2. aissh：接近“伴随 SSH 调查”的产品形态

- 本地优先的 SSH AI 工作区，官方明确不要求远端常驻 Agent、守护进程或预装采集脚本。
- 结合命令输出和服务器上下文进行调查，并提供主机状态面板；通过标准 SSH 和目标主机已有工具获取信息。
- 默认调查命令需批准；自动批准模式与本项目“自主探索、学生完成教学操作”的规则并不相同。
- 可参考自然语言提问、调查结果回流和主机状态组织方式。
- 外部 CLI 并非唯一模型接入方式，官方也支持直接配置模型 API；需要与主要依赖外部 CLI 的桥接项目区分。

来源：[官方仓库](https://github.com/friparia/aissh)。

## 3. korTTY：终端内自主调查与本地模型参考

- 官方网站说明 Agent 可在活动 SSH 会话内调查环境、规划并执行命令，远端无需额外安装组件。
- 官方仓库提供本地模型能力、SSH 与本机 Shell，以及 Agent 功能说明。
- 内置 AI Agent 可从应用菜单、终端菜单或本地拦截的快捷指令启动，使用应用配置的模型，不依赖外部 Agent CLI。
- 差异：以运维和修复任务为目标，实际变更可以在批准后执行；教学用途应保留学生操作环节。
- 官网与仓库显示的版本号存在差异，本次不据此断言具体版本可用性。

来源：[官方网站](https://kortty.app/)、[官方仓库](https://github.com/chardonnay/korTTY)。

## 4. Warp：存在免安装路径，但须区分 SSH 扩展

- 官方功能表说明：Warpified SSH 会话在不安装 SSH 扩展时，仍支持 Agent 对话、远端命令执行及基于终端的搜索。
- Warp 有自己的内置 Agent，第三方 CLI Agent 集成是另一项可选能力；本项目参考前者。
- 可选 SSH 扩展会在远端安装伴随服务，用于文件树、原生文件读写、代码索引等更完整能力，因此不能将全部 SSH 功能称作免安装。
- Legacy wrapper 是免安装回退方案，但会对支持的 Shell 进行会话级 bootstrap，且有平台、Shell 与嵌套 SSH 限制。

来源：[SSH 功能支持表](https://docs.warp.dev/code/ssh-feature-support)、[免安装回退机制](https://docs.warp.dev/terminal/warpify/ssh-legacy)、[可选远端扩展](https://docs.warp.dev/terminal/warpify/ssh/)。

内置 Agent 来源：[Warp Agents 官方说明](https://docs.warp.dev/agents/)。

## 5. 补充参考：Terminai 与 Wave Terminal

- [Terminai](https://github.com/emosenkis/terminai) 将本地 Agent 通过 MCP 接入所包装的终端，提供终端状态读取和批准后的输入能力。适合研究终端包装方案；本次没有找到同样明确的完整 SSH 支持保证，且官网标注为 alpha，Windows 仅有有限验证，不列为已确认完全匹配项。
- [Wave Terminal](https://docs.waveterm.dev/connections) 具有终端、SSH 和 AI，但其远端增强能力涉及可选 `wsh`。仅根据连接文档不能确认禁用 `wsh` 后完整自主 SSH 探查的覆盖范围，不列为已确认完全匹配项。

## 对本项目的设计结论

以下是基于上述机制的设计推论，不是已完成的实现或测试结果。

1. 远端预装 Agent 不是必需条件；本地客户端可以向 Agent 提供 SSH 命令执行、终端上下文和 SFTP 文件读取工具。
2. 同一交互 PTY 与独立 SSH exec 通道各有用途：前者接近学生当前 Shell 状态，后者不占用学生输入，但不自动共享目录和会话变量。
3. 免安装不等于完全不在远端运行代码；探查命令、临时脚本与会话内 bootstrap 仍可能在远端运行，需要在方案中明确。
4. 重点验证：学生切换目录、激活虚拟环境、进入容器/Pod、前台运行交互程序、经过跳板机及嵌套 SSH 后，探索是否仍指向正确环境。
5. 现有项目的主要目标是运维或开发。本项目的差异应落在学生教学：允许主动探索，解释证据与原理，按需给出分级提示，把教学操作留给学生，并结合课程 RAG 与学习记录。

## 补充技术选型：在客户端嵌入 Pi

这是一项待确认的 Agent 运行时选型，不是另一个终端成品。

- 官方 SDK 支持嵌入 Node.js/Bun，提供会话、工具、事件和上下文管理；可用于本项目右侧对话栏，无需学生另装 Pi CLI。
- 初版可优先评估 `pi-coding-agent` SDK，复用会话持久化、压缩及生命周期能力；若需要完全控制应用层会话，可使用更底层的 `pi-agent-core`。
- 官方扩展机制支持自定义工具，并说明可通过可替换 operations 将工具接到 SSH 或容器。本项目仍需实现终端上下文读取、目标会话路由、探索执行及取消逻辑。
- 默认工具不能直接沿用为远端操作工具，必须显式绑定目标会话；教学用途也需控制文件修改与任务代做能力。
- 建议由客户端 Pi 承担 Agent 循环，Django 提供课程检索、学习数据与模型服务代理；不在两端同时维护同一轮 Agent 状态。
- 当前官方仓库由旧 `badlogic/pi-mono` 地址重定向至 `earendil-works/pi`，官方文档采用 `@earendil-works/*` 包名；实现时需锁定版本，避免混用旧 `@mariozechner/*` 示例。
- 本次仅核对文档，尚未验证 Electron 打包、模型工具调用兼容性或 SSH 实际行为。

来源：[Pi SDK](https://pi.dev/docs/latest/sdk)、[自定义与远端工具](https://pi.dev/docs/latest/extensions#remote-execution)、[Agent Core](https://github.com/earendil-works/pi/tree/main/packages/agent)、[官方仓库](https://github.com/earendil-works/pi)。
