日期：2026 年 10 月 31 日。保留原 GPU 单机基线，新增用户提供的双机及四机 DGX Spark 方案；三套作为互斥备选，尚未选定最终采购方案。

两套新价格均按整套输入，不按单机再乘数量，也不与原 GPU 单机叠加采购。是否包含税费、保修、安装、QSFP 互连线缆及交换设备、具体 NVMe 容量尚未说明；未覆盖费用单列，不能将上述价格当作完整教学系统总价或已经验证的交付报价。

固定业务部分仍是四台 x86 服务器：控制平面 32 GB DDR3、两个 Worker 各 16 GB DDR3、独立数据机 32 GB。数据机仍采用 2 TB SSD 与 4×2 TB HDD RAID10。CPU、主板和硬盘型号暂不指定。

## 平台和网络

DGX Spark 使用 Arm CPU 与 Blackwell GPU，128 GB 为 CPU/GPU 共享的统一系统内存，并非 128 GB 独立显存。其系统使用 DGX OS；业务机维持原 Linux/x86 规划，通过模型 API 对接，所以不要求业务 K8s 与推理平台使用同一 CPU 架构。[NVIDIA 硬件说明](https://docs.nvidia.com/dgx/dgx-spark/hardware.html)

NVIDIA 提供两至四台 Spark 的 ConnectX-7/QSFP 互连指导。普通业务千兆交换机负责业务网络，不能代替跨机模型并行所需的高速互连。按实际拓扑确认直连、线缆或高速交换设备；报价已包含的部分不重复采购，未包含的部分单列。[官方多机连接说明](https://build.nvidia.com/spark/connect-multiple-sparks)

多机内存不会自动成为一个可随意分配的连续内存池；模型分片、并行和每节点峰值由推理引擎实现。两台或四台共同运行一个模型不等于已有多个独立模型副本，也不直接承诺课堂并发或容错能力。

## 模型与 64k 验证

按用户提供的“DeepSeek v4.1 1017”采用官方模型名 **DeepSeek-V4.1-Flash-1017** 记录。[官方模型说明](https://huggingface.co/deepseek-ai/DeepSeek-V4.1-Flash-1017)

官方仓库当前文件总量约 510 GB，这是下载体量，不等同于实际运行内存。由此不能承诺双机 256 GB 可完整常驻当前官方检查点；四机 512 GB 也不能仅比较总量就断言有足够运行余量。两套均需明确量化文件、卸载方式、推理引擎、逐节点分配和质量验证结果，不能借用原 Qwen 的权重与 KV 缓存估算。[官方文件清单](https://huggingface.co/deepseek-ai/DeepSeek-V4.1-Flash-1017/tree/main)

项目上下文继续按 **65536 token** 管理：完整输入 60000、输出 4096、余量 1440，初始仍限制为一个活动模型请求。该限制适用于三套方案，不因换硬件或模型而自动增加上下文或并发。

验证重点为：模型加载与内存峰值、约 48k/60k 长输入预填充、首 token 等待与持续生成、跨机通信、工具调用与思考结果解析、流式返回、取消，以及原教学案例。官方提供专用提示编码与协议工具；不能只替换模型名称就认定 Pi/网关已经适配。[官方提示编码说明](https://huggingface.co/deepseek-ai/DeepSeek-V4.1-Flash-1017/blob/main/encoding/README.md)

## 预算接入

令 B 为四台业务/数据服务器、数据 SSD/HDD、独立备份、普通网络、串口工位、UPS 和部署人工的预备费前合计；N2/N4 为双机/四机报价未覆盖的推理互连及必要配套费用。则：

- P1：`首次预算 = 1.10 × (B + 10000 + 500)`。
- P2：`首次预算 = 1.10 × (B + 80000 + N2)`。
- P3：`首次预算 = 1.10 × (B + 160000 + N4)`。

B、N2、N4 尚未补齐报价，未知值不能按 0 处理。Spark 方案不额外叠加原 T10 的 10000 元整机和 500 元导风配套。UPS、维护人工及运维功耗应按 5/6/8 台分别复核，不能机械沿用原两台或五台部署的费用。

完整预算变量见[正式方案](项目设计方案.md) e3–e5。本次仅补充选型与费用输入，不实际部署模型或集群。
