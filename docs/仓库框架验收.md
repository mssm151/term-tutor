## 实际验证结果

使用 PowerShell 7 和 `D:\anaconda\envs\py311\python.exe`（Python 3.11.9）。为避免改变已有 Conda 环境中的 Django 版本，本次将 `requirements.txt` 安装到被 Git 忽略的 `artifacts/check-deps/`，验证进程通过 `PYTHONPATH` 引入 Django 5.2.18。该临时目录无需提交；使用者按根目录 README 将依赖安装到自己的 Conda 环境即可。

| 检查 | 结果 |
|---|---|
| Django `check` | 通过，0 个问题 |
| Django `test tests --noinput` | 6 项测试通过 |
| Django `migrate --noinput` | 自带 admin/auth/contenttypes/sessions 表迁移成功 |
| GNU Make 入口 | 使用已有 `mingw32-make` 验证 help、check、test、migrate，通过；确认调用指定 py311 |
| 实际 HTTP 启动检查 | 临时 `runserver --noreload`，`GET /api/health/` 返回 200、`framework-only`；验证后服务器已关闭 |

六项测试检查：存活接口、框架入口、七个业务路由的未实现响应、HTTP 方法限制、CSRF 保留、后端不开放终端执行接口。

本次 Make 验证命令如下，`PYTHONPATH` 仅用于隔离本次依赖：

```powershell
$env:PYTHONPATH = "$PWD/artifacts/check-deps"
mingw32-make help
mingw32-make check
mingw32-make test
mingw32-make migrate
```

`make install` 的依赖清单已通过单独的 pip 安装验证；未用该目标修改共享 Conda 环境。`make run` 对应的 Django 启动命令已进行上述临时 HTTP 检查。
